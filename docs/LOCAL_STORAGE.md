# 本地数据持久化约定

## 结论

属性较多、重新录入成本高的计算器表单，必须保存到当前浏览器的 `localStorage`，并在页面重新加载后自动恢复。

新增字段不会自动进入本地存储。开发时必须同步更新状态结构、读取校验、保存逻辑和恢复测试。

## 保存范围

必须保存：

- 角色面板计算器中的潜力方案、各类属性加成配置和是否计入装备值的开关。
- 角色面板统一设置的角色等级，以及角色装备计算器中的八件装备、宝石及突破状态、属性词条、独立词条、开关和特效配置。
- 三个角色存档位；每个存档包含存档名称、完整角色面板配置、共享角色等级和八件装备配置。
- 灵兽面板中的等级、0 级五维、潜力方案、资质、成长、亲和、三件灵兽装备原始配置、两件灵饰原始配置、装备计入开关与各类加成来源。
- 三个灵兽存档位；每个存档包含存档名称和完整灵兽面板配置。
- 后续新增的高输入量计算器表单，包括需要用户逐项录入或配置较多字段的工具。

默认不保存：

- 可以根据输入重新计算的结果和汇总值。
- 错误提示、加载状态、当前弹窗、当前页签等临时界面状态。
- 敏感信息、令牌或任何不应暴露给浏览器脚本的数据。

少量、一次性输入的转换器是否保存，应根据重新录入成本单独判断，不要求所有计算器无条件持久化。

## 当前存储键

| 用途                       | localStorage key                      |
| -------------------------- | ------------------------------------- |
| 角色面板配置               | `mz-tools.character-attributes.v2`    |
| 共享角色等级与八件装备配置 | `mz-tools.equipment-attributes.v2`    |
| 三个角色存档位             | `mz-tools.character-profiles.v1`      |
| 灵兽面板配置               | `mz-tools.spirit-beast-attributes.v2` |
| 三个灵兽存档位             | `mz-tools.spirit-beast-profiles.v1`   |
| 计算器选择偏好             | `mz-tools.preferences.v1`             |
| 本地收藏                   | `mz-tools.favorites.v1`               |

版本号是数据结构的一部分。存在不兼容变更时，应升级 key 的版本，并明确选择迁移旧数据或安全回退默认值。

装备配置 v2 在根状态中保存角色面板与装备共用的角色等级，并为每件装备增加宝石配置。等级只支持 69、89、110；旧缓存中的其它等级会映射到最近档位并同步收紧宝石等级。读取不到 v2 时会自动从 `mz-tools.equipment-attributes.v1` 迁移原有八件装备，角色等级使用默认值 69；旧 key 暂时保留用于兼容，不再写入。

旧装备缓存中分开保存的基础属性和铸灵属性会在读取时合并为游戏面板展示的最终装备属性；后续保存不再保留独立铸灵字段。

角色面板配置 v2 将灵符从自由数值改为“星级 + 属性选项”。读取不到 v2 时会从 `mz-tools.character-attributes.v1` 恢复其他角色配置，旧版灵符自由数值不迁移；旧 key 保留兼容，不再写入。

三生造化丹按五维分别保存用户已服用的原始颗数，属性点由“颗数 × 2”实时计算；旧版 v2 缓存缺少该字段时自动使用 0 颗，不需要升级存储 key。

潜力点配置保存常见 / 自由模式、自由规则和每级五维原始点数。自由加点是 v2 的兼容新增字段；旧缓存继续恢复原常见方案，非法或缺失的自由配置安全回退为对应规则的默认 10 点方案，不需要升级存储 key。

装备计入开关属于角色面板配置，关闭后只排除装备对角色面板结果的影响，不修改或清空八件装备；旧缓存缺少该字段时默认计入装备值。

天书星魂按已选择的固定选项 ID 保存，每项最多保存一次；这是角色面板配置 v2 的兼容新增字段，旧缓存缺少该字段时默认不选择，不需要升级存储 key。

赛季神器的等级属性按固定选项 ID 和已选次数保存，每项最多选择 2 次；恢复缓存时更大的次数会收紧为 2。原有单选五维潜能点字段保持不变，旧缓存缺少等级属性字段时默认不选择，不需要升级存储 key。

琥珀朱绫使用独立布尔字段保存是否佩戴，不占用原有三种互斥法宝的 `talismanOptionId`；旧缓存缺少该字段时默认不佩戴，不需要升级存储 key。

灵兽面板配置 v2 保存全部原始输入，不保存公式计算结果，也不保存当前弹窗和加成显示状态。资质收紧到 900～1800，成长收紧到 1.000～1.500；宝衣、宝链、宝冠分别保存开关和原始属性行，装备汇总实时计算；1 阶、2 阶灵饰分别保存计入状态、随机属性类型和实际数值，固定全资质加成实时计算；技能、命格和坐骑统御仍按来源保存合计加成。三件装备和两件灵饰均属于 v2 的兼容字段，旧缓存缺少时补空白配置；旧版直接录入的装备、灵饰合计继续兼容叠加，并在对应编辑器中提供清理入口。损坏缓存或未知字段会安全回退默认通用配置，旧测试版 v1 数据不迁移。

灵兽存档 v1 固定提供三个槽位，保存名称与完整灵兽面板原始输入；恢复时覆盖当前灵兽面板配置。存档不会保存计算结果、当前弹窗或加成显示状态，单个损坏槽位会安全回退为空槽。

## 新增计算器或字段检查清单

1. 判断它是否属于高输入量表单；属于时必须接入本地存储。
2. 在 `src/utils/calculatorStorage.ts` 中定义独立、带版本号的 key。
3. 首次渲染时读取缓存，并对未知、缺失和非法字段进行校验或补默认值。
4. 用户输入变化后保存原始配置，不保存可重新计算的结果。
5. 新增角色面板字段时，同步更新 `CharacterCalculatorState`、默认值、标准化逻辑、保存对象和 effect 依赖。
6. 新增装备字段时，同步更新 `EquipmentItem` 和 `normalizeEquipmentItem`；类型检查必须能够发现遗漏。
7. 增加“修改字段 → 卸载或刷新 → 恢复字段”的测试，并验证损坏缓存不会阻断计算器。
8. 运行 `pnpm lint`、`pnpm test --run` 和 `pnpm build`。

## 为什么暂时使用 localStorage

当前数据是少量 JSON 配置，通常只有几 KB。`localStorage` 实现简单，不需要新增依赖，也足够支持页面刷新后的恢复。

出现以下需求时再升级方案：

- 需要保存大量方案、历史记录或明显超过普通表单规模的数据：考虑 IndexedDB。
- 需要账号登录、跨设备同步、共享或备份：使用后端数据库，不能只依赖浏览器存储。

本地数据仅属于当前浏览器和当前站点。清除网站数据、使用隐私模式或更换设备后，数据可能丢失。
